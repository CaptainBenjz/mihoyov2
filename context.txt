-------------------------------------------------------------------------------
PROJECT OVERVIEW
-------------------------------------------------------------------------------
A premium, Genshin Impact-only Telegram bot (python-telegram-bot v21.9, async).
Links a player's Genshin UID and retrieves public account info, showcased
characters + full builds, Spiral Abyss, Imaginarium Theater, banners, and build
recommendations via public APIs (Enka.Network via `enka`, Akasha via akasha.cv).
No Honkai/ZZZ features. This is the backend-foundation phase; premium UI/image
layouts come later. Business logic is separated from rendering; all external
calls are async and cached.

-------------------------------------------------------------------------------
REPOSITORY STRUCTURE
-------------------------------------------------------------------------------
bot/
  main.py            entrypoint: builds Application, wires handlers, run_polling
  config.py          pydantic-settings; reads .env (BOT_TOKEN, REDIS_URL, ...)
  app_context.py     AppContext dependency container (built in post_init)
  commands/          thin Telegram handlers -> services
  services/          business logic (no Telegram/rendering)
  api/               enka_client.py (Enka wrapper), akasha_client.py (raw aiohttp
                     to akasha.cv; the pip akasha-py client is NOT used — 403 UA)
  database/          redis_client.py (async pool, TLS upgrade), store.py (RedisStore)
  cache/             redis_cache.py (JSON, TTL, prefix "cache")
  renderer/          Renderer abstraction + Pillow backend (card layouts)
  models/            framework-agnostic dataclasses + serialize.py (cache <-> model)
  translations/      i18n.py + locales/*.json (en default, per-key fallback)
  assets/            loader.py (dynamic, placeholder fallback) + bootstrap.py (startup
                     download of card template + Noto font)
  utils/             logging, errors, callbacks (callback_data encode/decode), text
tests/               pytest suite (fakeredis; no network)
scripts/             run_local.sh, watchdog.sh
data/                (gitkeep; sqlite legacy paths gitignored)
AUDIT_REPORT.md      full audit with severity levels (see it for details)

Datastore: Redis (Upstash-compatible) is the primary source of truth. Degrades
gracefully if Redis is briefly unavailable; the bot never crashes on API/Redis
failures, private profiles, empty showcases, rate limits, or timeouts.
